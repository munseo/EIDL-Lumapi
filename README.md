Gradient Ascent Optimization Module for Adjoint Optimization
============================================================

## Conda setup

Create the conda environment from the repository root:

```bash
cd /home/eidl/EIDL-Lumapi
conda env create -f setting/environment.yml
conda activate EIDL-Lumapi
resource
```

On the first `resource` or `run` command, EIDL-Lumapi writes a one-time config
file at `$CONDA_PREFIX/.eidl_lumapi_config.json`. It tries to detect:

- license settings from `ANSYSLMD_LICENSE_FILE`, `LUMERICAL_LICENSE`,
  `LM_LICENSE_FILE`, `~/.config/Lumerical/License.ini`, or `~/ansys_license`
- installed Lumerical versions under `/opt/lumerical/v*`
- Lumerical API and binary paths for the detected version

If Lumerical is not installed but an extracted install tree or `.tar.gz` archive
is available, set this before the first `resource` or `run` command:

```bash
export EIDL_LUMERICAL_INSTALLER=/path/to/lumerical-installer-or-tree
```

The first-run setup can copy a detected `v*` install tree into
`$CONDA_PREFIX/lumerical/`. RPM installers still require manual/system
installation and will be reported as such.

The environment installs this repository in editable mode, so `msopt` can be
imported from any working directory after the environment is activated:

```bash
python -c "import msopt as ms; print(ms.Opt_MS2.__name__)"
```

Simulation scripts should use one package import:

```python
import msopt as ms

sim = ms.Lumerical_utill.LumericalFDTDSimulator(...)
optimizer = ms.Opt_MS2.OPT_Ms(...)
```

## Commands

Check available Lumerical/GPU resources:

```bash
resource
```

Run a simulation script with explicit Lumerical CPU threads and GPU assignment:

```bash
run script_name.py -th 8 -GPU 2
```

This sets `FDTD_THREADS=8`, pins the run to CPU cores `0-7` by default, sets
`CUDA_VISIBLE_DEVICES=2`, and sets `LUMERICAL_SESSION_GPU_DEVICE="GPU 2"`.
Use `--no-taskset` if CPU affinity should not be pinned. Output is written to
`/Lumerical_data/<timestamp>_<tag>/` when that path is writable. Otherwise,
`run` automatically falls back to `~/Lumerical_data/<timestamp>_<tag>/`.

The simulation process runs with the selected output directory as its current
working directory, so relative Lumerical outputs such as `.fsp` files and other
generated byproducts are collected there. To force a specific location, use:

```bash
run script_name.py -th 8 -GPU 2 --outdir /path/to/Lumerical_data
```

Enable profiling when you want per-step CPU, memory, child-process, and GPU
usage records:

```bash
run script_name.py -th 8 -GPU 2 --profile
```

Profiling output is written to `profiling_results/` inside the run directory.
